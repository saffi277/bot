## 1. المبادئ غير القابلة للتفاوض

هذه قرارات مثبَّتة من المالك. لا تخالفها ولا تعِد اقتراح بدائل عنها.

1. **الموقع هو المنتج، والبوت قناة ومنتج معاً** (قرار المالك 2026-09-06).
   بعد `/start` يختار الزبون: يعمل داخل البوت، أو يفتح الموقع. فإن اختار
   البوت أرسل صورة فتُرمَّم وتُرجَع إليه.

2. **الترميم يتم بنماذج ذكاء اصطناعي.**
   فلاتر Canvas لا تستطيع بلوغ نتيجة Remini — راجع `DISCUSSION.md §2`.
   شعار «بدون ذكاء اصطناعي» أُلغي ويجب ألا يبقى منه أثر في الكود أو النصوص.

3. **لا يوجد نظام دفع في هذه المرحلة.** ولا نجوم تلگرام.

4. **سقف الدقة إلزامي قبل أي نداء للمزوّد.**
   إرسال صورة بدقتها الأصلية للمزوّد يضاعف الفاتورة **15 مرة**. المُخرَج
   المعتمد: **سقف 2048px على الضلع الطويل**.

   4b. **الواجهة بلا ضبط يدوي.** رفع → معالجة تلقائية → مقارنة قبل/بعد →
   تنزيل. لا sliders ولا إعدادات جاهزة — كانت من منطق الفلاتر القديم.

   4c. **لا وعود توليدية.** v1 اسمه «ترميم وتحسين تلقائي للصور والوجوه».
   النموذج لا يَعِد بإعادة بناء عضو ناقص. التوقّع يُوضَّح في الواجهة قبل أول
   رفع — الوعد الزائد أكبر مسبّب للتقييمات السيئة.

5. **كل نداء للنماذج يمر عبر `lib/enhance/provider.ts`.**
   ممنوع استدعاء مزوّد مباشرةً من أي مسار API أو مكوّن واجهة. سبب ذلك أن
   الانتقال لسيرفر GPU خاص عند ~50 ألف صورة/شهر يجب أن يكون بتبديل ملف واحد،
   كما أن **تبديل النموذج حسب المستوى** (§3.3) يمر من النقطة نفسها.

6. **كل مسار يعالج صوراً يمر عبر `lib/ratelimit.ts` قبل استدعاء المزوّد.**
   هذا صمّام الأمان الوحيد ضد استنزاف الفاتورة.

## 2.1 الأمان — ما يجب معرفته قبل التعديل

**`middleware.ts` يفرض CSP على كل استجابة.** المصادر المسموحة اليوم: خطوط
Google (`fonts.googleapis.com` و`fonts.gstatic.com`)، وودجت دخول تلگرام
(`oauth.telegram.org`)، و`blob:`/`data:` للصور التي تنشئها الصفحة.

> ⚠️ **أي مصدر خارجي جديد يُحجب صامتاً** — بلا خطأ في الشاشة. إن أضفت خطاً أو
> سكربتاً أو صورة من نطاق آخر، أضِفه في `middleware.ts` أولاً وإلا لن يظهر ولن
> تعرف لماذا.

**تنبيه:** vinext يحمّل الـmiddleware عند الإقلاع لا عبر HMR. بعد تعديله أعد
تشغيل الخادم، وإلا ظهر لك أنه لا يعمل.

**رفع الصور يُتحقَّق منه بالبايتات** (`lib/image-type.ts`) لا بـ`file.type`،
لأن الأخير يكتبه العميل — فكان بإمكان أي طرف إرسال أي بيانات باسم صورة
وإنفاق الميزانية عليها.

**أسرار المشروع:** `TELEGRAM_WEBHOOK_SECRET` و`TELEGRAM_SESSION_SECRET`
و`ADMIN_TOKEN` تُقارَن بزمن ثابت، والمسارات المحمية بها **تفشل مغلقة**.

## 3. الواجهة المجرّدة للمزوّد

هذا هو العقد الأهم في المشروع. أي مزوّد جديد يطبّق هذه الواجهة، ولا يتغيّر شيء
آخر. الحقول المؤشَّرة أضافها Codex في مراجعة `DISCUSSION.md §8.1`.

```ts
// lib/enhance/provider.ts

export type EnhanceRequest = {
  image: ArrayBuffer;
  /** MIME type of the input, so the provider does not have to sniff it */
  inputContentType: string;
  /** Longest output edge. Default 2048 — see ARCHITECTURE.md §1.4 */
  maxOutputEdge: number;
  /** Restoration strength 0..1 — realism against identity preservation */
  fidelity: number;
  /** Trace id, carried through logs and the provider call */
  requestId: string;
};

export type EnhanceResult = {
  image: ArrayBuffer;
  contentType: string;
  /** Output megapixels — the unit the provider bills on */
  outputMegapixels: number;
  /** Model that actually ran, for cost attribution across models */
  model: string;
  requestId: string;
  /** Wall-clock duration — decides whether async processing is needed */
  durationMs: number;
};

export interface EnhanceProvider {
  readonly name: string;
  enhance(request: EnhanceRequest): Promise<EnhanceResult>;
}
```

**قواعد:**

- المزوّد لا يعرف شيئاً عن تلگرام ولا المستخدمين ولا الحدود اليومية.
- `outputMegapixels` و`durationMs` **إلزاميان** — بدونهما لا يمكن تتبّع التكلفة
  الفعلية ولا حسم قرار المعالجة غير المتزامنة.
- أي فشل من المزوّد يُرمى كاستثناء؛ التعامل معه مسؤولية مسار الـ API.
- **الطابور داخلي.** إن استخدم المزوّد طابوراً للطلبات الطويلة فذلك يبقى داخل
  `lib/enhance/gemini.ts`؛ العميل لا يرى حالة وظيفة إطلاقاً. راجع
  `DISCUSSION.md §8.4`.

### 3.1 سجلّ الاستخدام — إلزامي

يُسجَّل في D1 لكل طلب: `requestId`, `model`, `outputMegapixels`, `durationMs`,
والنتيجة (نجاح/فشل). بدونه تبقى الفاتورة تخميناً.

### 3.3 اختيار النموذج — قرار سياسة، لا قرار مزوّد

**مستوى الجودة قرار منتج وتسعير، فلا يدخل `provider.ts`.** المزوّد منفذٌ غبيّ
ينفّذ ما يُطلب منه؛ **مسار الـAPI** هو من يختار أي مزوّد يُستدعى وبأي سياسة.
هذا يحفظ التجريد نظيفاً ويمنع تسرّب قرارات التسعير إلى طبقة البنية.

```
app/api/enhance/route.ts   ← يقرأ السياسة ويختار المزوّد
        ↓
EnhanceProvider            ← ينفّذ فقط، لا يعرف عن المستويات شيئاً
```

**v1: مزوّد واحد فقط.** لا يُطرح مستوى مدفوع قبل أن يحسم الاختبار المقارَن
(`DISCUSSION.md §10.6`) أي نموذج يستحق.

**عند تفعيل مستوى أعلى لاحقاً:**

- يُضاف كـ **تطبيق ثانٍ للواجهة نفسها**، ويُختار في مسار الـAPI — لا بحقل في
  عقد المزوّد.
- **لا يُستدعى تلقائياً أبداً.**
- **لا يُحتسب بوزن ثابت في الحدود.** يُحجَز **بالكلفة الفعلية بالدولار قبل
  الطلب**، لأن النِسَب تتغيّر بتغيّر أسعار المزوّدين: Nano Banana Pro اليوم
  **20 ضعف** CodeFormer لا 7.

⚠️ أسعار الاستدعاء التفاعلي هي المرجع، **لا أسعار Batch** — مسار Batch غير
متزامن ولا يصلح لطلب ينتظر المستخدم نتيجته.

## 3.2 الحدود اليومية — ثلاث طبقات

الحد لكل مستخدم **لا يحمي الفاتورة** وحده: 5,000 مستخدم × 5 صور = $165 في يوم.
لذلك يعلو الحدَّين الفرديين سقفٌ إجمالي.

| الطبقة | المتغيّر | القيمة الأولية | ما تحميه |
|---|---|---|---|
| لكل زائر (IP) | `LIMIT_GUEST_DAILY` | 3 | الاستنزاف الفردي بلا تسجيل |
| لكل حساب تلگرام | `LIMIT_USER_DAILY` | 5 | الاستنزاف الفردي المسجَّل |
| 🔴 سقف إجمالي | `DAILY_GLOBAL_CAP` | 250 | **سقف الفاتورة الشهرية** |

عند بلوغ السقف الإجمالي يرد الموقع برسالة عربية مهذّبة **ولا يُستدعى المزوّد
إطلاقاً**. القيم كلها من متغيّرات بيئة لتُضبط بلا إعادة نشر.

`DAILY_GLOBAL_CAP = 250` يعني سقف فاتورة ≈ **$50/شهر**. المعادلة:

```
السقف اليومي = (الميزانية الشهرية ÷ $0.0066) ÷ 30
```

## 4. تدفّق الموقع

```
المستخدم يضغط بطاقة خدمة  →  ينفتح منتقي الصور فوراً
   ↓
تصغير في المتصفح لسقف الدقة      ← إلزامي. رافعة التكلفة الأهم
   ↓
POST /api/enhance   (image + operation)
   ↓
التحقق من بايتات الصورة          ← lib/image-type.ts، قبل أي حجز
   ↓
lib/ratelimit.ts — حجز الوحدات (Telegram ID أو IP)
   ↓
lib/enhance/provider.ts  ببرومبت الخدمة المختارة
   ↓
النتيجة → معاينة قبل/بعد → تنزيل
```

### 4.1 كتالوج الخدمات — `lib/enhance/operations.ts`

**مصدر واحد** يعرّف كل خدمة: المعرّف، النوع، الاسم المعروض، الشرح، الكلفة
بالوحدات، والبرومبت. إضافة خدمة **سطر بيانات** — لا مسار جديد ولا عدّاد.

| الحقل | المعنى |
|---|---|
| `kind: 'enhance'` | المسار الافتراضي: زر واحد، الذكاء يقرّر. **الافتراضي دائماً من هذا النوع** |
| `kind: 'creative'` | يختارها المستخدم عمداً لأنها تُنتج صورة **مختلفة** |
| `units` | **عدد نداءات النموذج**. يجب أن يطابقها فعلاً — وحدة على خدمة تنادي أربع مرات تُشغّل الإنفاق بأربعة أضعاف السقف بصمت |

`GET /api/enhance` يرجع `operations` بلا البرومبتات. **الواجهة تُبنى منها،
لا من قائمة مكتوبة بيدها** — وإلا انحرفت عن الباك-إند.

`npm run test:ops` يحرس هذا: معرّفات فريدة، وحدات صحيحة، الافتراضي من نوع
`enhance`، وكل برومبت يحمل قاعدة حفظ الهوية ومنع الإطار.

## 5. تدفّق البوت

```
/start
   ↓
«وين تحب تسوي صورك؟»
   ├── هنا بالبوت → يرسل صورة → ترميم → ترجع إليه
   ├── بالموقع    → زر + وسم ?ref= لقياس المصدر
   └── شلون يشتغل؟ → الدليل الثلاثي
```

**مسار الصورة في البوت:**

| المرحلة | الملاحظة |
|---|---|
| القبول | `message.photo` فقط. الملف (`document`) يُرفض — يصل بلا ضغط، وصورة هاتف 12MP تكلّف **$0.10 بدل $0.007** |
| التصغير | **يقوم به تلگرام** (~1280px). لا canvas في Worker، وهذا ما يحلّ محلّه |
| التوقيت | الرد بـ200 **فوراً**، والمعالجة في `waitUntil`. الرد المتأخّر يجعل تلگرام يعيد الإرسال — أي فاتورة مضاعفة على صورة واحدة |
| الحدود | `reserve()` نفسها. الهوية `user:<telegram_id>` فيأخذ حصّة المسجَّلين |
| الفشل | `release()` عند `safeToRelease` فقط — المهلة قد تكون فُوترت |

## 5.1 تقرير المالك — `GET /api/stats`

محمي بـ`ADMIN_TOKEN`، ويرد **404 لا 401** عند غيابه أو خطئه: مسار يعلن أنه
مقفل فقط دعوة للتخمين. يقرأ `usage_log` ويرجع لكل نافذة زمنية: عدد الصور
الناجحة والفاشلة، نسبة النجاح، الزوّار المميّزين، الكلفة التقديرية، الوسيط
وp95، ومن أين جاء الزوّار.

`npm run stats` يطبعه بشكل مقروء. يستدعي الموقع المنشور لا قاعدة البيانات،
لأن D1 في الإنتاج لا تُقرأ إلا من داخل الـWorker.

## 7. متغيّرات البيئة

| المتغيّر | الغرض |
|---|---|
| `APP_URL` | عنوان الموقع الذي يفتحه زر البوت |
| `TELEGRAM_BOT_TOKEN` | توكن البوت من BotFather |
| `TELEGRAM_BOT_USERNAME` | معرّف البوت بلا `@`. بدونه لا يظهر زر الدخول |
| `TELEGRAM_WEBHOOK_SECRET` | سرّ التحقق من تلگرام. **بدونه يرفض الويبهوك كل تحديث** |
| `TELEGRAM_SESSION_SECRET` | يوقّع كوكي الدخول. **مستقل عن التوكن عمداً** — تدويره بخلاف ذلك يطرد كل المستخدمين. فارغاً ⇒ وضع الزائر |
| `ADMIN_TOKEN` | يفتح `GET /api/stats`. ٣٢ حرفاً على الأقل، وإلا رد المسار 404 |
| `GEMINI_API_KEY` | مفتاح النموذج. بدونه يعمل الموقع ويرفض المعالجة |
| `ENHANCE_MODEL` | تجاوز اسم النموذج. الافتراضي `gemini-3.1-flash-image` |
| `GEMINI_API_BASE` | تجاوز عنوان الواجهة — للاختبار أو لـVertex AI |
| `TELEGRAM_API_BASE` | تجاوز واجهة تلگرام — للاختبار بخادم مزيَّف |
| `D1_BINDING` | اسم ارتباط قاعدة العدّادات. الافتراضي `DB`. **غيابه يوقف المعالجة** |
| `MAX_OUTPUT_EDGE` | سقف الضلع الطويل للمُخرَج. الافتراضي `2048` |
| `LIMIT_GUEST_DAILY` | حد الزائر غير المسجَّل. الافتراضي `2` |
| `LIMIT_USER_DAILY` | حد حساب تلگرام. الافتراضي `5` |
| `DAILY_GLOBAL_CAP` | 🔴 السقف الإجمالي اليومي. الافتراضي **`16`** — أي `16 × 30 × $0.101 ≈ $48/شهر` |

> **تصحيح (2026-09-06):** كان هذا الجدول يذكر `250` سقفاً افتراضياً و`3` للزائر،
> والكود `16` و`2` منذ جولة 9 حين صُحِّح سعر النموذج. الفارق **خمسة عشر ضعفاً**
> في وثيقة موضوعها حماية الفاتورة — وهو نوع الخطأ الذي يُبنى عليه قرار خاطئ.

القيم الحقيقية **لا تدخل الگت أبداً**. `.env.example` يوثّق الأسماء فقط.

## 8. قواعد المساهمة

- **تحقّق قبل الدفع:** `npm run lint && npm run build` يجب أن يمرّا نظيفين.
- **لا تُسكِت خطأً لتمرّ البناء.** أصلح السبب.
- **لا تضف اعتماديات** إلا لحاجة حقيقية؛ المشروع خفيف عمداً.
- **النصوص للمستخدم بالعربية**، وتعليقات الكود بالإنجليزية.
- **عند تعديل قرار في `DISCUSSION.md`** حدّث الملف مع تاريخ التعديل، حتى يبقى
  الوكيل الآخر على علم.
