# إطلاق البوت — خطوة بخطوة

**البوت يرمّم الصور بنفسه** (قرار المالك 2026-09-06): بعد `/start` يختار الزبون
— يشتغل داخل البوت أو يفتح الموقع. فإن أرسل صورة، تُعالَج وتُرجَع إليه.

يمكن إطلاق كل شيء اليوم **بلا مفتاح النموذج**: التدفّق كامل، والمعالجة وحدها
تعتذر بوضوح حتى يُضاف المفتاح.

---

## ما يفعله المالك بيده

### 1. إنشاء البوت

افتح **@BotFather** في تلگرام:

```
/newbot
```

يسألك عن اسم ظاهر، ثم عن معرّف ينتهي بـ`bot`. يعطيك بعدها **التوكن** —
سطر طويل يشبه `1234567890:AA...`

**احفظه ولا تضعه في الگت أبداً.**

### 2. المتغيّرات

**على جهازك للتجربة:** `npm run setup:env` يسأل ويكتب `.env.local` بنفسه،
ويولّد السرّين. لا تحرّر شيئاً بيدك.

**وللنشر:** القيم نفسها تُضبط في إعدادات الاستضافة (لا في ملف داخل المستودع):

| المتغيّر | القيمة |
|---|---|
| `TELEGRAM_BOT_TOKEN` | التوكن من BotFather |
| `TELEGRAM_BOT_USERNAME` | معرّف البوت بلا `@` |
| `TELEGRAM_WEBHOOK_SECRET` | أي نص عشوائي طويل تخترعه |
| `TELEGRAM_SESSION_SECRET` | نص عشوائي آخر، ٣٢ حرفاً على الأقل — **غير التوكن** |
| `ADMIN_TOKEN` | نص عشوائي ثالث. يفتح تقرير الاستخدام — اختياري |
| `GEMINI_API_KEY` | مفتاح النموذج. بدونه يعمل كل شيء عدا المعالجة |
| `APP_URL` | عنوان الموقع بعد النشر |

> `npm run setup:env` يسأل عن التوكن واسم البوت، **ويولّد الأسرار الثلاثة
> بنفسه**. لا تخترعها بيدك.

`TELEGRAM_WEBHOOK_SECRET` ليس شكلياً: **بدونه يرفض الويبهوك كل تحديث** ولا يرد
البوت إطلاقاً. اخترناه يفشل مغلقاً لأن البديل — تخطّي التحقق — يعني أن أي طرف
يعرف العنوان يقدر يقود البوت.

`TELEGRAM_SESSION_SECRET` يوقّع جلسة الدخول في الموقع. **لا تجعله نفس التوكن:**
تدوير التوكن حينها يطرد كل المستخدمين من حساباتهم. وإن تركته فارغاً يبقى الموقع
في وضع الزائر ويعمل طبيعياً — الدخول بتلگرام وحده يتعطّل.

### 3. نشر الموقع

تلگرام يحتاج عنواناً عاماً يصل إليه. الويبهوك لا يُسجَّل قبل أن يكون الموقع
منشوراً ويستجيب.

### 4. تسجيل الويبهوك

```bash
npm run bot:webhook
```

يقرأ القيم من `.env.local` تلقائياً — الذي أنشأه `npm run setup:env`. لا حاجة
لتصدير أي متغيّر بيدك.

يسجّل الويبهوك ويضبط `/start` و`/help`.

> **تشغّل هذه الخطوة بنفسك، لا الوكيل.** بيئة عمل الوكيل تحجب
> `api.telegram.org` بسياسة الشبكة، فلا يستطيع تسجيل الويبهوك ولا فحصه من
> هناك. الأمر نفسه ينطبق على `npm run bot:doctor`.

### 5. الفحص

```bash
npm run bot:doctor
```

يسأل تلگرام **والموقع** ويقول أين الخلل بالضبط: هل الموقع يستجيب؟ هل قاعدة
العدّادات مربوطة؟ هل وصل المفتاح؟ هل شُحنت ترويسات الأمان؟

**شغّله قبل أن تظن أن شيئاً معطّل** — بوت تلگرام يفشل صامتاً، والسبب لا يظهر
من نافذة المحادثة.

يميّز بين ما **يمنع الإطلاق** (`[FAIL]`) وما هو **ملاحظة** (`[note]`) كمفتاح
لم يُضَف بعد. الملاحظات لا تمنع شيئاً.

### 6. التجربة

افتح البوت وأرسل `/start`. المتوقّع: ترحيب، ثم دليل من ثلاث خطوات بأزرار،
وزر يفتح الموقع.

---

### 7. تابع ما يجري

```bash
npm run stats
```

يقول لك كم صورة عولجت، كم فشلت، **كم صرفت**، وكم زبوناً جاءك من البوت مقابل
الموقع. يحتاج `ADMIN_TOKEN` في الجهتين — عندك وفي المنصة.

---

## ما يبقى لاحقاً

| البند | متى |
|---|---|
| `GEMINI_API_KEY` | عندما تريد تشغيل الترميم فعلياً |
| `/setdomain` في BotFather | عندما تريد تفعيل الدخول بتلگرام من الموقع |

قبل مفتاح النموذج، الموقع يعلن بوضوح أنه تحت التجهيز ولا ينهار. البوت يعمل
كاملاً في هذه الحالة.

---

## حين لا يرد البوت

**شغّل `npm run bot:doctor` أولاً.** يميّز بين:

| العرض | السبب |
|---|---|
| التوكن غير صالح | أُلغي أو نُسخ ناقصاً |
| سرّ الويبهوك فارغ | يرفض كل تحديث — يفشل مغلقاً بقصد |
| الويبهوك غير مسجَّل | لم يُشغَّل سكربت التسجيل |
| الويبهوك على عنوان قديم | تغيّر `APP_URL` ولم يُعَد التسجيل |
| رسائل معلّقة | الموقع لا يستجيب — تحقق من النشر |
| خطأ 401 من الويبهوك | السرّ لا يطابق ما سُجِّل |

الخمسة تبدو متطابقة من المحادثة: البوت ساكت. الأداة تفرّق بينها في سطر.
